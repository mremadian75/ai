# Next Sprint Plan — Real WordPress Staging Bugfixes

## Objective

Validate the staging-browser-ready build in a real WordPress browser session and patch only evidence-backed bugs.

## Plan

1. Install on WordPress staging.
2. Activate plugin and capture activation logs.
3. Configure provider callback secret.
4. Complete workspace onboarding in Command Room.
5. Start Brand & Market X-Ray.
6. Run signed callback simulator dry-run.
7. Send valid signed callback to staging.
8. Run bad-signature, stale timestamp and replay checks.
9. Run provider fixture callbacks.
10. Inspect Provider Ingestion Ledger.
11. Inspect Run Timeline diagnostics.
12. Approve/reject Insight, create Brief, generate Draft.
13. Record Outcome.
14. Inspect Decision Map and private Decision Report.
15. Generate evidence pack.
16. Capture browser screenshots.
17. Patch only bugs reproduced by staging evidence.

## Explicit non-goals

- Do not connect real third-party providers yet.
- Do not treat the optional n8n example as a required path.
- Do not add a public self-serve launch surface.
- Do not add autonomous publishing.
- Do not add new modules unrelated to staging validation.
