# Release Evidence Pack — Specification (schema 1.0)

Phase 9B.3. A live staging validation may only be recorded as **passed** through
a structured, hash-verified evidence pack. A bare
`wp option update ves_rc_live_validation …` is classified **unverified_manual**
and is never trusted.

## File

JSON, generated by `wp ves rc-evidence-pack --output=<folder>` and completed by
`scripts/future-island-live-validation-v2.sh` (which attaches the captured
command outputs and recomputes the hash).

## Required fields

| Field | Type | Meaning |
| --- | --- | --- |
| `schema_version` | string | `"1.0"` |
| `build_sha256` | 64-hex | SHA-256 of the installed plugin ZIP |
| `plugin_version` | string | `FIS_VERSION` at generation time |
| `siteurl`, `home` | string | staging site identity |
| `wp_version`, `php_version`, `db_version` | string | environment facts |
| `command_outputs` | map | command → `{output_sha256, exit_code}` |
| `screenshots_manifest` | array | filenames of the captured screenshots |
| `php_error_log_sha256` | 64-hex or `""` | hash of the captured log tail |
| `browser_console_log_sha256` | 64-hex or `""` | hash of the console export |
| `generated_at` | UTC datetime | generation time |
| `operator` | object | `{name, user_id}` |
| `validation_status` | enum | `passed` / `failed` / `incomplete` — **computed, never asserted** |
| `limitations` | array | honest caveats |
| `evidence_pack_hash` | 64-hex | deterministic SHA-256 (below) |

## Required command outputs (exit code 0 each)

```
php -v
wp core version
wp option get siteurl
wp ves verify-schema
wp ves validate-staging --format=json
wp ves rc-readiness-check --format=json
wp ves memory-summary --format=json
wp ves operator-queue --workspace=1 --format=json
wp ves memory-expire --dry-run
```

`validation_status` becomes `passed` only when every one of these is present
with exit code 0 and a non-empty output hash, and an operator name is set.

## Deterministic hash

`evidence_pack_hash = sha256( canonical_json(pack minus evidence_pack_hash) )`
where `canonical_json` sorts object keys recursively (lists keep order) and
encodes compactly (no whitespace, unescaped slashes/unicode). Any edit to the
pack after hashing invalidates it. If a cross-tool hash mismatch ever occurs,
regenerate the pack rather than hand-editing it.

## Recording

```
wp ves rc-record-live-validation --evidence-pack=/path/evidence-pack-….json
```

Refuses when: schema invalid · hash mismatch · `validation_status != passed` ·
any required command output missing/non-zero · current `rc-readiness-check`
blockers exist. On success it stores
`{status: passed, source: evidence_pack, evidence_pack_hash, build_sha256,
recorded_at, operator}` — and the build is **still not production-ready**.

## Classification rules (readiness + RC page)

| Stored state | Classified as |
| --- | --- |
| nothing | `unrun` |
| any option without `source=evidence_pack` + valid 64-hex hash | `unverified_manual` |
| pack-recorded state | `passed` (hash displayed, truncated, escaped) |

`wp ves rc-readiness-check --strict` blocks unless the classification is
`passed`; its best result is `ready_for_pilot_review` — never production-ready.
